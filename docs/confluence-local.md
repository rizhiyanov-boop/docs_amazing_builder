# Публикация в Confluence через локальный сервис

DocBuilder публикует отдельный метод в выбранный пользователем Confluence через сервис на его компьютере. HTTPS-адрес Confluence и PAT вводятся в локальной форме; подключение хранится только в памяти процесса. Сервер DocBuilder и его опубликованный frontend токен не получают. Адрес заранее не задан; до подключения сервис не выбирает Confluence автоматически.

## Запуск

Нужен Node.js 22 или новее. Сервис не использует сторонние npm-пакеты, не требует npm install и административной установки. Отсутствие Node.js или запрет на запуск исполняемых файлов корпоративной политикой остаются ограничениями среды; эта поставка их не обходит.

В архиве релиза распакуйте все файлы в одну папку и запустите start-confluence.cmd. В исходном проекте аналогичный файл находится в scripts/confluence/start.cmd. Оставьте открытым окно сервиса. В нём появится адрес http://127.0.0.1:18771/; откройте его в браузере.

Launcher последовательно ищет Node.js в runtime/node.exe рядом с собой, в переменной NODE_EXE, в локальном runtime Codex пользователя, затем в PATH. Архив без runtime/node.exe требует уже доступный Node.js. Чтобы явно выбрать исполняемый файл:

```powershell
$env:NODE_EXE = 'C:\Tools\node\node.exe'
.\start-confluence.cmd
```

Прямой запуск из корня исходного проекта:

```powershell
node scripts/confluence/server.mjs
```

В форме укажите HTTPS Origin вашего Confluence, например https://confluence.example.com, без пути страницы, логина, query и fragment. Затем вставьте личный токен доступа Confluence и нажмите «Подключить». Проверка отправит PAT только указанному экземпляру Confluence. После проверки вернитесь в DocBuilder и нажмите «Проверить подключение». Парольная форма очищает поле сразу после отправки; сервис не публикует страницу при подключении. Закрытие вкладки с формой не останавливает сервис.

Интеграция использует REST API Confluence Server/Data Center и PAT Bearer. Для конкретного экземпляра должны быть доступны соответствующие методы чтения, Wiki-конвертации и записи, а для диаграмм — описанные ниже плагины. Совместимость с другим контрактом авторизации или API Confluence Cloud в этом релизе не заявляется.

Для завершения сессии нажмите «Забыть токен» в локальной форме или остановите сервис сочетанием Ctrl+C. После перезапуска PAT нужно ввести снова. Сессия длится 30 дней после последнего успешного запроса к Confluence; чтение одного локального статуса её не продлевает. Срок PAT и серверная политика Confluence действуют независимо от этого локального срока.

## Разрешённые адреса

Сервис слушает только 127.0.0.1. Проверка Host допускает только 127.0.0.1:порт и localhost:порт. Confluence upstream определяется HTTPS Origin, который пользователь ввёл в локальной форме. HTTP, URL с логином или паролем, путь, query и fragment отклоняются до отправки PAT. Адрес и PAT не записываются в настройки, файл или браузерное хранилище; после перезапуска подключение нужно ввести заново. Перенаправления отключены; PAT не пересылается на адрес из Location или из ссылки пагинации.

К API по умолчанию допускаются только следующие Origin:

- https://docsamazingbuilder.vercel.app;
- http://localhost:5173;
- http://127.0.0.1:5173.

Дополнительный точный HTTPS Origin разрешается только аргументом запуска. Шаблоны, произвольные домены и пути не принимаются:

```powershell
node scripts/confluence/server.mjs --origin https://your-docbuilder.example
```

Опубликованный DocBuilder ожидает сервис на порту 18771. Другой порт предназначен для разработки или собственной сборки frontend с изменённым адресом bridge; переключение порта в пользовательском интерфейсе этого релиза не предусмотрено:

```powershell
node scripts/confluence/server.mjs --port 18772
```

Frontend использует заголовок X-DocBuilder-Request со значением 1. Все вызовы API, кроме получения локального статуса, дополнительно передают X-DocBuilder-Confluence-Origin с точным ожидаемым Origin текущего Confluence. Подготовка и публикация передают тот же baseUrl в теле запроса. Несовпадение с действующей локальной сессией возвращает SESSION_CHANGED до чтения или записи: запрос не может переключить PAT на другой сервер.

Preflight разрешает только GET, POST, Content-Type, X-DocBuilder-Request и X-DocBuilder-Confluence-Origin; Private Network Access разрешается в ответе только на соответствующий запрос браузера. Cookies и PAT для hosted API не нужны. Локальная форма подключения имеет отдельный nonce, проверку собственного Origin и ограничивающую CSP; hosted frontend не получает этот nonce.

Каждая операция захватывает конкретное подключение. Если пользователь меняет Confluence или повторно подключается во время выполнения, сервис не продолжает следующие обращения с новым PAT или адресом. После уже отправленной записи такая смена может оставить результат неизвестным; перед новой публикацией его нужно проверить на исходном экземпляре.

Браузер может отдельно запросить доступ сайта к локальной сети или запретить его корпоративной политикой. CORS/PNA-заголовки сервиса поддерживают такое подключение, но не отменяют браузерное разрешение. Для сетевых ошибок сначала проверьте запуск сервиса, разрешение браузера, доступ к Confluence и VPN. Ошибка сертификата не исправляется отключением проверки TLS: установите доверенную корпоративную цепочку обычным согласованным способом.

## Дерево и данные проекта

При открытии экрана DocBuilder загружает все порции доступных пространств в память. Меню показывает недавние пространства и каталог с поиском по названию или ключу. Личные пространства скрыты в каталоге по умолчанию и включаются переключателем; в недавних они остаются доступными. Названия берутся из Confluence без перевода. Фильтр категории / тега использует metadata.labels; если эти сведения не переданы, фильтр недоступен. Для него нужен обновлённый локальный сервис.

В localStorage браузера сохраняются только три ключа недавно выбранных в DocBuilder пространств, отдельно для каждого адреса Confluence. Названия, категории и дерево туда не записываются; при следующем открытии названия снова загружаются, а недоступные пространства не показываются в недавних. Это история выбора в DocBuilder, а не история посещений Confluence.

Каждый запрос дерева заново обращается к Confluence. Первая порция содержит корневые страницы пространства; раскрытие узла запрашивает его детей. Сервис возвращает следующий offset для «Загрузить ещё» и не выгружает всё пространство автоматически. Для детей дополнительно проверяется принадлежность родителя выбранному пространству. Неожиданный ответ с вложенными страницами вместо корней считается ошибкой.

Дерево, страницы и результат подготовки не записываются сервисом в файлы, localStorage, IndexedDB или БД. Ответы имеют Cache-Control: no-store. На стороне DocBuilder дерево живёт в памяти открытого экрана и очищается при его закрытии. До перезагрузки приложения отдельно запоминаются выбранные пространства публикации и просмотра и идентификаторы раскрытых ветвей; при возвращении данные этих ветвей читаются заново. Локальный статус подключения проверяется каждые пять секунд без перечитывания дерева; проверка статуса не подтверждает сетевую доступность Confluence и не продлевает локальную сессию. Сохранение обычного проекта DocBuilder не запускает полную выгрузку Confluence.

В проекте допускается привязка метода к странице: адрес экземпляра, пространство, pageId, последняя опубликованная версия, отпечаток и дата публикации. Хранение самого проекта остаётся существующим: локальность PAT не делает содержимое проекта локальным. Если проект использует серверное автосохранение, эта привязка и исходные данные проекта сохраняются тем же способом.

## Создание и обновление

Подготовка использует POST /rest/api/contentbody/convert/storage для преобразования Wiki в Confluence storage. Диаграммы передаются отдельным исходным текстом и заменяют заранее выделенные маркеры в полученном storage. PlantUML публикуется макросом plantuml с параметром INLINE, Mermaid — макросом mermaiddiagram. CDATA корректно разделяется при последовательности ]]> в исходнике. Автоматическая отправка диаграмм на mermaid.ink или plantuml.com отсутствует.

Сервис не управляет настройками установленных на Confluence плагинов. Возможные внешние обращения самого плагина при рендеринге зависят от конфигурации Confluence; это проверяется администратором отдельно. Подтверждение сохранённого storage и исходного кода не доказывает успешную отрисовку SVG плагином. После публикации предусмотрена ссылка на страницу Confluence для визуальной проверки.

Кнопка «Опубликовать» выполняет подготовку и запись последовательно, без промежуточного экрана подтверждения. Для новой страницы пользователь выбирает родителя в дереве. Перед созданием повторно читается родитель и проверяется пространство. Право записи окончательно подтверждает Confluence при POST /rest/api/content. Локальный API сохраняет совместимость с явным созданием в корне, но интерфейс этот вариант не предлагает.

Перед обновлением повторно читается существующая страница. Несовпадение текущей версии с ожидаемой возвращает VERSION_CONFLICT до записи. PUT /rest/api/content/pageId отправляет следующую версию; дополнительный конкурентный конфликт Confluence также блокирует обновление. Автоматического перезаписывания чужих изменений нет.

Успешный ответ POST/PUT подтверждает публикацию, если он содержит страницу в статусе current, pageId, пространство, название, ожидаемую версию и предков. Сервис проверяет эти метаданные, включая родителя при создании, и сразу возвращает результат для сохранения привязки. Дополнительное чтение и сравнение HTML для такого ответа не требуются: Confluence вправе нормализовать storage при сохранении. Параметр expand=space,version,ancestors запрашивает нужные метаданные в ответе записи.

Если успешный ответ содержит только pageId или неполные метаданные, сервис повторно читает страницу и проверяет назначение, версию и storage. При таком чтении и восстановлении потерянного ответа сравнение storage допускает различие генерируемых macro-id, переводов строк и эквивалентную замену &nbsp; на символ неразрывного пробела вне CDATA. Содержимое CDATA, включая код и диаграммы, не преобразуется. Остальные изменения XML требуют проверки перед подтверждением неопределённого результата.

## Неопределённый результат и повторные попытки

POST и PUT не повторяются автоматически. Если связь потерялась после отправки записи, сервер вернул 5xx, ответ содержит противоречивые метаданные или проверка неполного ответа не подтвердила результат, возвращается OUTCOME_UNKNOWN. Это означает, что страница могла быть создана или обновлена. Полноценный успешный ответ записи не переводится в OUTCOME_UNKNOWN из-за последующей недоступности страницы или нормализации HTML.

Операции хранятся только в памяти процесса. В журнале находятся идентификатор, состояние, адрес известной страницы, ожидаемые метаданные и SHA-256 нормализованного storage; полный storage, предки страницы, дерево и PAT в журнал не помещаются. Чтение результата требует активной сессии и заново проверяет доступ к странице. Максимум — 256 записей. При заполнении вытесняется самая старая подтверждённая или завершившаяся известной ошибкой операция. Выполняющиеся и неизвестные результаты не вытесняются; если ими заполнен весь журнал, новая публикация блокируется до проверки результата. Идемпотентный ответ для старой завершённой операции доступен, пока её запись есть в журнале.

Повтор с тем же operationId после подтверждённого успеха возвращает прежний результат без записи. При pending или unknown запись блокируется. Новый operationId для того же назначения, названия, ожидаемой версии и содержимого также блокируется, пока исходная операция pending или unknown; ответ содержит исходный operationId. Генерация нового macro-id для той же диаграммы эту защиту не обходит.

Журнал привязан к исходному Origin Confluence. Смена сервера не удаляет неизвестную операцию и не позволяет подтвердить её по совпадающему pageId на другом экземпляре. Для проверки сначала подключитесь к исходному Confluence; после удаления или истечения PAT журнал не выдаёт метаданные без действующей сессии.

GET /api/operation заново проверяет страницу, если её pageId уже известен. Когда повторное чтение подтверждает сохранение, операция становится success без новой записи. Если ответ создания потерян и pageId неизвестен, пользователь открывает Confluence и указывает найденную страницу. POST /api/operation/confirm выполняет только GET на исходном экземпляре и подтверждает именно ожидаемое пространство, название, родителя, версию и содержимое. Несовпадение возвращает VERIFICATION_MISMATCH; подтверждённую другую страницу подставить нельзя.

После остановки процесса журнал исчезает. Если экран неопределённого результата остаётся открытым, его исходный снимок позволяет проверить ссылку и восстановить привязку после переподключения. POST /api/operation/confirm принимает этот снимок только для отсутствующей в журнале операции и проверяет страницу чтением: исходный адрес, название, пространство, родителя или pageId, версию и нормализованный storage. Эта проверка ничего не создаёт и не обновляет. При наличии операции в журнале источником ожиданий остаётся журнал, снимок не подменяет его. После перезагрузки самого DocBuilder снимок теряется. Защита от дубликатов относится к текущему процессу и не обещает устойчивую идемпотентность после перезапуска.

## Локальный контракт

Это внутренний протокол связи frontend с локальным bridge, не публичный контракт банковского интеграционного адаптера. Он использует согласованные модели src/confluenceTypes.ts без enterprise-wrapper. Ошибка возвращается как объект code и message; при блокировке неопределённой или выполняющейся операции дополнительно возвращается operationId. Текст и тело внешней ошибки не пересылаются в frontend и не логируются.

| Метод и путь | Назначение |
| --- | --- |
| GET /health | Несекретное состояние запуска сервиса |
| GET /api/status | Состояние локальной сессии, адрес Confluence и срок |
| GET /api/spaces?start=0&limit=50 | Порция доступных пространств |
| GET /api/tree?spaceKey=DI&start=0&limit=50 | Корневые страницы пространства |
| GET /api/tree?spaceKey=DI&parentId=10&start=0&limit=50 | Порция дочерних страниц |
| GET /api/page?id=10 | Актуальная страница, предки, версия и storage |
| POST /api/prepare | Конвертация wiki и diagrams в storage без публикации |
| POST /api/publish | Создание или обновление по ConfluencePublishRequest |
| GET /api/operation?id=operationId | Состояние и повторная проверка известного pageId |
| POST /api/operation/confirm | Проверка найденной страницы для неизвестного результата |

Основные коды: NOT_CONNECTED и AUTH_EXPIRED — подключиться заново; SESSION_CHANGED — обновить состояние подключения и проверить исходное назначение; ACCESS_DENIED — проверить права; NOT_FOUND — проверить адрес и видимость страницы; VERSION_CONFLICT — загрузить изменения; OPERATION_PENDING — дождаться операции; OUTCOME_UNKNOWN — проверить результат; VERIFICATION_MISMATCH — указанная страница не подтверждает публикацию; UPSTREAM_UNAVAILABLE — сеть или Confluence; UPSTREAM_INVALID — неожиданный формат ответа; UPSTREAM_REDIRECT — перенаправление заблокировано. Секреты не включаются в ответы и диагностические сообщения.

## Проверка разработки

Автотесты запускают поддельный upstream только на 127.0.0.1 и используют искусственный токен. Они не обращаются к корпоративному Confluence и не записывают реальные страницы:

```powershell
node --test scripts/confluence/bridge.test.mjs
```

В среде, где изоляция Node test runner не может создать дочерний процесс, поддерживается запуск без такой изоляции:

```powershell
node --test --experimental-test-isolation=none scripts/confluence/bridge.test.mjs
```

Тестовый upstream и transport задаются программно только при импорте createBridge. HTTP-адрес на 127.0.0.1 допускается только при явном allowTestUpstream; в тестовой локальной форме он должен совпадать с этим адресом. Проверка переключения между HTTPS Origin использует вымышленные домены и подменённый transport, который физически обращается только к локальному fake-серверу. Production-код требует HTTPS, не отключает проверку TLS и не выводит PAT в лог.
