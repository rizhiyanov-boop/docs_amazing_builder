# Вложенные параметры: UX переименования

Статус: UX утверждён и реализован в рабочем React-редакторе.

## Цель и границы

Сохранить принадлежность параметра объекту или массиву при редактировании имени. Разрешить менять имя родителя в его строке с обновлением путей всех потомков одной операцией.

Первый этап: переименование узлов внутри существующей таблицы Request/Response, простой режим и Server/Client. Не добавлять перенос узлов, drag-and-drop строк, сворачивание дерева, массовое переименование, смену вложенности, удаление поддерева или преобразование object/array в скаляр.

## Подтверждено исходниками

- src/types.ts: ParsedRow содержит field, sourceField, необязательный id и признаки источника; явного parentId нет.
- src/parsers.ts: вложенность JSON/JSON Schema представлена путями; для массива используются обозначения элементов, например [0]. Объекты и массивы могут иметь собственные строки. XML дополнительно использует исходный путь, атрибуты и другие специальные обозначения.
- src/App.tsx: startFieldEditing передаёт в инпут полный row.field. saveFieldEditing меняет field одной найденной строки; каскадного переименования нет.
- Редактирование открывается двойным кликом или карандашом. Enter и потеря фокуса сохраняют, Escape отменяет. Tab/Shift+Tab перемещают редактор по строкам в той же колонке.
- Текущий редактор использует Inter для UI, JetBrains Mono 13 px для технических значений, иконки 16 px, нейтральные границы и тёплый акцент. Колонка поля уже закрепляется при достаточной ширине.

Далее описан утверждённый UX. Результаты проверки реализации приведены в конце документа.

## Основной паттерн

Сохранить обычную таблицу, полный путь и ширины колонок. Не вводить отдельный режим «дерево» и постоянную панель управления структурой.

В колонке поля родительский путь показывать вторичным цветом, имя текущего узла — основным. Оба остаются читаемыми и доступными для выделения и копирования. Разбивка по точкам сохраняется; не использовать новый набор цветов для уровней вложенности. Отступами не уменьшать полезную ширину фиксированной колонки.

Карандаш доступен постоянно с умеренным контрастом. Один клик по имени не начинает редактирование. Двойной клик и Enter/Space на карандаше открывают один и тот же инпут.

## Редактирование

1. Заменить только имя текущего узла инпутом на том же месте. В фокусе и выделении только имя узла. У корневого параметра инпут занимает место корневого имени, у вложенного — последнего сегмента пути.
2. Родительский путь и обозначение элемента массива остаются обычным неизменяемым текстом рядом с инпутом, на прежнем месте. Не переносить их на новую строку при открытии редактора.
3. Не добавлять кнопки сохранения и отмены. Место карандаша сохранять в раскладке, скрывая его на время ввода. Геометрия ячейки и высота строки при входе и выходе из редактирования одинаковы.
4. Enter и уход из корректного инпута сохраняют. Escape возвращает прежнее значение.
5. Для объекта/массива с потомками в существующей строке статуса вне тела таблицы показать «Обновятся пути 2 вложенных полей». Считать все затронутые строки потомков, включая вложенные контейнеры; сам редактируемый узел в число не включать.
6. Инпут не увеличивается при вводе длинного имени; текст прокручивается внутри него. Не создавать вторую строку с подсказкой внутри ячейки. Сообщения и ошибки используют заранее отведённое место вне таблицы.
7. Tab/Shift+Tab сохраняют корректное значение и открывают имя следующей/предыдущей доступной строки в той же колонке, как в текущем редакторе. На границе таблицы фокус выходит обычным порядком.

Не создавать поповер, модальное окно, выезжающий тулбар или новое автопрокручивание всей страницы. Открытие инпута, ввод, ошибка и отмена не меняют координаты строк. Изменение длины уже сохранённого имени может повлиять на естественный перенос полного пути; это изменение данных, а не раскрытие редактора. Остальные строки не менять до сохранения. При горизонтальном скролле использовать существующее обеспечение видимости активного контрола.

## Переименование родителя

Пример: customer → buyer.

- Строка customer становится buyer.
- customer.name становится buyer.name.
- customer.profile.email становится buyer.profile.email.
- Соседний customerInfo не изменяется.
- Порядок строк, описания, примеры, обязательность, типы и маскирование сохраняются.
- Операция атомарная: либо применены все изменения, либо ни одно.
- Один Undo возвращает имя родителя и все дочерние пути. Не создавать отдельное действие Undo для каждой строки.
- После сохранения показать ненавязчивый результат через существующий механизм статуса: «Имя сохранено · Обновлены пути 2 вложенных полей». Не окрашивать все потомки в акцент и не добавлять второй набор кнопок Undo.

Подтверждение для каждого родителя не требуется: воздействие видно до сохранения, действие обратимо. Отдельная модалка существенно замедлит последовательное редактирование таблицы.

## Массивы

Имя массива меняется в строке контейнера: orders → purchases. В orders[0].amount редактируется только amount; orders и [0] остаются структурным контекстом.

Безымянная строка элемента, например orders[0], не имеет собственного имени для переименования. Не показывать ей неработающий карандаш и не подменять индекс пользовательским именем. Обозначение элемента сохранять в принятом исходным форматом виде; данная фича не меняет [0] на [].

Вложенные массивы и объекты обрабатываются тем же правилом: меняется один именованный узел, его потомки наследуют новый путь.

## Конфликты и ошибки

| Ситуация | Сообщение и поведение |
| --- | --- |
| Пустое имя | «Введите имя параметра». Сохранение не выполняется. |
| Имя соседа уже занято | «Имя уже занято на этом уровне. Выберите другое имя». Редактируемое значение и его родитель видны в самой строке. Не объединять узлы автоматически. |
| Вставлен полный путь | Для однозначного структурного пути: «Введите только имя. Родительский путь здесь не меняется». Не обрезать вставленный текст молча и не перемещать поле. |
| При каскаде возник бы конфликт путей | Оставить черновик и прежние данные. Показать первый конфликтующий путь; не выполнять частичное обновление. |
| Отмена | Восстановить прежнее отображение и вернуть фокус карандашу текущей строки. |
| Ошибка при уходе из поля | Оставить ввод и ошибку доступными, не применять изменение и не очищать черновик. Не перехватывать фокус постоянно; Escape всегда позволяет выйти. |
| Имя не изменилось | Закрыть редактор, не добавлять запись в историю. |

Ошибку показывать в отведённой строке статуса вне тела таблицы; инпут обозначить цветом ошибки и связать с сообщением через aria-describedby и aria-invalid. Не добавлять строку под инпутом и не менять высоту ячейки. Цвет дополняет текст, а не заменяет его. Смена черновика убирает устаревшую ошибку после исправления.

Не вводить общий запрет на пробелы, кириллицу, дефисы и другие допустимые исходным форматом символы. Правила имени определяются форматом и структурой, а не универсальным regex для идентификатора.

## Server/Client и синхронизация

- Переименование в Server меняет только Server; Client автоматически не переименовывается. Обратное правило аналогично.
- Выбор соответствия в колонке Client request/response остаётся операцией маппинга, а не редактором имени Server.
- Связи должны продолжать указывать на тот же логический узел. Нельзя удалять и заново угадывать маппинг по похожему имени.
- sourceField и клиентский исходный ключ не перезаписываются простым переименованием отображаемого пути.
- Состояние расхождения с исходником и явное обновление JSON/XML сохраняют существующую семантику. Не обещать пользователю, что исходный payload уже изменился, если выполнено только переименование таблицы.
- Undo должен сохранять целостность связей, а не только возвращать видимый текст.

## Неоднозначные случаи: граница MVP

Иерархию нельзя восстанавливать простым split по точке для любого значения.

| Случай | Предлагаемая обработка |
| --- | --- |
| Header, query, URL-параметр с точкой | Считать имя литеральным, пока источник явно не задаёт вложенность. |
| JSON-ключ сам содержит точку/скобки | Сохранить литеральное имя и точное структурное значение. До надёжного распознавания не предлагать каскад на основе строки. |
| XML namespace, атрибут, текстовый узел | Защитить структурные маркеры. Разрешать только то переименование, которое поддерживает XML-модель и синхронизация; не применять правила JSON автоматически. |
| В импортированной таблице нет строки родителя | Листовое имя можно менять с сохранением префикса. Не создавать фиктивный параметр ради UX. Переименование отсутствующего родителя — отдельный случай после согласования его представления. |
| Связь родителя неоднозначна | Не угадывать поддерево и не выполнять каскад. Сохранить исходную таблицу; объяснить, что структурное переименование для этого пути недоступно. |

Это ограничения представления текущей модели, а не дополнительные бизнес-правила. Для полного охвата JSON/XML/Schema необходимо отдельно проверить структурную адресацию. MVP можно выпускать на однозначно распознанных JSON/Schema-узлах, сохраняя действующее поведение остальных форматов; нельзя молча объявить их поддержанными.

## Foundation / Components / Patterns

- Foundation: новых токенов и шрифтов не требуется. Использовать существующие цвета текста, мягкий фон выбора, цвет ошибки, размеры иконок и инпутов.
- Components: расширить существующий редактор имени поля. Выделять общий компонент только если он действительно заменяет дублирование Server/Client, а не создаёт параллельный редактор таблицы.
- Patterns: один редактируемый узел, неизменяемый контекст, атомарное каскадное переименование, локальная ошибка и общий Undo.
- Это изменение UX и поведения данных. Его нельзя поставлять как одну косметическую CSS-правку.

## Условия готовности к внедрению

1. Проверены лист, объект, массив объектов, массив скаляров и вложенный массив.
2. customer и customerInfo не смешиваются; одинаковые имена в разных родителях допустимы.
3. Проверены коллизия имени соседа, коллизия итоговых путей, пустое имя и вставка полного пути.
4. Переименование и Undo сохраняют описания, обязательность, маскирование, источники и связи Server/Client.
5. Карандаш, двойной клик, Enter, Escape, сохранение при blur и вертикальный Tab дают согласованный результат. Отдельных кнопок сохранения и отмены нет.
6. Не прыгает страница при открытии/закрытии редактора; закреплённая колонка и ресайз остаются работоспособны.
7. Длинный путь и узкая область не скрывают инпут, ошибку и действия; при ошибке нет потери текста или ловушки фокуса.
8. Неоднозначные имена, отсутствующие родители и специальные XML-узлы имеют явное поддерживаемое поведение до релиза.

## Интерактивное предложение

В диалоге подготовлен отдельный интерактивный макет на вымышленных JSON-узлах. После его утверждения паттерн внедрён в рабочий React-редактор. Пользовательские документы для проверки не использовались: браузерный стенд запускается на отдельном локальном origin с вымышленными данными.

Первоначальное раскрытие ячейки с отдельным путём, двумя кнопками и подсказкой отклонено: оно меняло высоту строки. Текущая редакция заменяет имя инпутом на том же месте; статусы вынесены из таблицы.

В браузере измерены координаты и высоты всех строк при ширине 736 px: открытие редактора корня и вложенного поля, ввод длинного имени, конфликт имён и отмена дают нулевой сдвиг. При 320 px открытие вложенного поля и ошибка полного пути также не меняют геометрию строк. Дополнительно проверены каскадное переименование двух потомков, общий Undo и переход Tab к следующему имени после сохранения. Это проверка макета, а не регрессионная проверка рабочего редактора.

Проверка рабочей реализации: высота строк сохраняется при открытии инпута, вводе длинного имени и ошибке. После первоначального позиционирования таблицы автоматизацией повторное открытие также не меняет её координаты. В браузере проверены каскад customer → buyer, сохранение связи с payload.reference и возврат всех путей одним Undo.

В коде проверяются структурные имена, массивы, совпадения префиксов, конфликты итоговых путей, литеральные query/header-имена и неоднозначные имена из JSON/Schema/cURL. Для обычных XML-путей защищены @, namespace-префикс и #text; неоднозначные XML-имена не получают каскадное переименование. Исходные ключи сохраняются до явной пересборки; при пересборке адреса Server/Client-маппинга переводятся согласованно.

Добавлено 14 тестов логики, UI и атомарной истории, включая переименование отдельного Client-контейнера с уже связанными дочерними полями. В отдельном подтверждающем прогоне 78 тестов прошли, 4 ранее отключённых теста пропущены. Первоначальный общий прогон имел 4 падения в импорте/Confluence; все четыре проверки прошли в подтверждающем прогоне. Модели хранения и публикационные привязки не изменены.
